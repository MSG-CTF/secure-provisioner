# Namespace 정리 완료 확인

Gateway 접속 경로를 제거하고 Pod 종료를 확인한 뒤에는 Namespace 삭제를
한 번 요청하고, 남아 있으면 정상 정리 대기로 돌려보냅니다 다음 작업에서도
같은 Namespace UID와 팀 소유권을 확인하며 실제 NotFound 전에는 완료로
처리하지 않습니다

기존에는 2초짜리 Gateway 정리 단계 안에서 조회를 반복했습니다 단계 종료와
조회가 겹치면 정상 finalization 대기가 취소된 API 조회로 바뀌고, 장애 재시도
간격까지 기다릴 수 있었습니다 이제 이미 삭제 중인 Namespace는 검증된 첫
조회 결과를 사용하고, 새 삭제 요청 뒤에도 조회를 한 번만 수행합니다

정상 대기는 기존 1초 progress 재시도를 사용합니다 API가 실제로 응답하지
않거나 오류를 반환하면 기존 장애 재시도를 유지합니다 일반 직접 삭제의
대기 방식은 유지하며, finalizer 제거·강제 Pod 종료·조기 예약 반납은 하지
않습니다 문제 코드·이미지·CPU 부스트·종료 hook도 변경하지 않습니다

이 변경은 Kubernetes 내부 컨트롤러의 처리 시간을 보장하지 않습니다
Namespace가 실제로 남아 있으면 바인딩과 예약을 유지해야 합니다
