# Kubernetes API 요청 예산 대기

삭제 작업이 짧은 제한 시간 안에 로컬 요청 예산을 확보하지 못하면 HTTP 요청을 보내기 전에 중단됩니다
이를 서버 장애와 구분해 다음 작업에서 다시 확인하도록 처리합니다
실제 Namespace가 사라진 것을 확인하기 전에는 삭제 완료나 예약 반납으로 처리하지 않습니다

공유 제한기는 오류 종류만 표시하며 삭제 어댑터에서만 정상 대기로 바꿉니다
생성·준비·CPU 원복 작업의 최대 시도 횟수와 실패 처리는 유지합니다
실제 HTTP 오류·통신 시간 초과·상위 작업 취소도 정상 대기로 바꾸지 않습니다
요청량 20 QPS와 burst 40은 그대로입니다

기존 보조 자원 선삭제는 운영 실측에서 속도 개선을 확인하지 못해 이번 변경에서 제외했습니다
Namespace 컨트롤러·finalizer·자원 삭제 순서는 현행 구현을 유지합니다

검증은 실제 client-go 제한기와 HTTP 서버를 사용해 요청이 전송되지 않는 대기와 실제 서버 오류를 구분합니다
이 시험은 실제 사이트의 삭제 속도나 브로커 반납 검증을 대신하지 않습니다
